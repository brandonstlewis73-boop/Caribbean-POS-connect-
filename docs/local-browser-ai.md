# Local browser AI testing

Open `/ai-test` while signed in with settings access. Enter a test request and click **Download & generate** to load the selected model. **Device AI** defaults to Higher quality (Qwen 2.5 1.5B); Lightweight (Qwen 2.5 0.5B) is available for devices with less memory. The choice is saved in browser storage when permitted. This page uses only your entered text and does not fetch business records or change plan entitlements.

The model runs in a Web Worker through WebLLM. The first run downloads about 870 MB of weights for Higher quality or about 300 MB for Lightweight, plus runtime files; browser caching depends on available storage. WebGPU, a secure HTTPS connection (or localhost), and sufficient device memory are required. On iPhone, open the site directly in Safari on iOS 26 or newer, which adds WebGPU support (https://webkit.org/blog/16993/news-from-wwdc25-web-technology-coming-this-fall-in-safari-26/). Close other apps and keep the tab in the foreground. A browser with WebGPU does not guarantee sufficient GPU memory. Desktop Chrome or Edge can also be used. Unsupported devices display a clear error. Downloads can take several minutes. Use Stop to cancel a download or generation on the test page. Closing or reloading the page also stops the worker. Startup, download, and generation have timeouts; worker failures are reported instead of leaving the button busy.

No OpenAI API calls or paid fallback remain. Existing OPENAI_API_KEY and AI_MODEL variables are ignored and can be removed from Vercel. AI_SUPPORT_ENABLED=false disables the business/support flows and owner test page. No AI key is needed.

Business tools and help chat still authenticate, enforce plan/usage restrictions, redact inputs, and prepare only the signed-in account's context on the server. Prepared requests are logged and count against existing usage limits, including cases where the device later fails to generate. Generated local drafts are displayed in the browser and are not stored in server logs. Ticket summaries use deterministic server heuristics instead of remote AI. This is local inference, not an offline version of the entire app: accounts, records, and support still require the application server.

The Qwen 2.5 0.5B and 1.5B Instruct models are Apache 2.0 licensed: https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct and https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct. WebLLM: https://webllm.mlc.ai/. Drafts need human review. Context is bounded for device memory and may contain selected records only.

Validation includes production compilation of the worker, server tests for prompt preparation/disabled mode/secret requests/no remote inference, and a browser test for unsupported devices and mobile layout. Actual model loading and generation must be tested on a physical WebGPU device; the execution environment has no suitable GPU.

The higher-quality model uses the float16 variant if the GPU adapter supports shader-f16, otherwise float32. WebLLM lists approximately 1.6 GB and 1.9 GB of GPU memory respectively; actual usage varies. No claim of compatibility with every iPhone is made. Changing models releases the previous worker before loading the next model.

The smaller 32-bit model needs approximately 1.1 GB of GPU memory according to WebLLM’s catalog and does not require shader-f16. Drafts stream on the test page and are limited to 256 output tokens. A GPU adapter check runs before downloading weights. The smaller model trades answer quality for lower memory use; physical-device testing is still required.

Draft validation checks explicitly requested price placeholders and unsupported first-person action promises. A completed invalid draft gets one model-generated correction attempt, then an error if it still fails. This is a limited check, not a guarantee of factual accuracy or overall quality. No canned promotion is automatically substituted for model output.

## AI Workspace

Open `/ai` and choose one of the 19 workflows available under your plan. The workspace provides a conversation area, suggested starting points, editable responses, and workflow-specific business context. Revisions include your edited response, original goal, and requested changes. Each preparation counts toward the existing AI allowance. Failed or stopped requests preserve your previous response. Switching workflows retains completed conversations in page memory; reloading clears them.

Product descriptions and promotions require selecting an actual product from the signed-in business catalog. Users with product write access can choose **Save to product** on a completed product description. The server validates authentication, role, plan, business ownership, and the original description. A transaction locks the product, updates only its description and timestamp, and records the audit event. Concurrent changes return a conflict instead of overwriting another user's work. Changing the selected product clears that conversation to prevent applying a response to the wrong product.

Results can be edited, copied, or downloaded as text. Message workflows offer **Open in WhatsApp**, which opens the result for the user to choose a recipient and send. It does not automatically send a provider message. Other workflows link to their business workspace; they do not automatically create orders, modify stock, dispatch deliveries, or save accounting entries.

Rendered-flow checks use mocked model/API responses and cover mobile/desktop layouts, all workflow choices, generation, edits, save payloads, revisions, failed-save and failed-revision recovery, clipboard, downloads, workflow retention, cancellation, and product isolation. Transaction tests verify permissions, tenant isolation, description conflicts, audit rollback, and preservation of prices and stock. Physical-device inference remains a separate check.

Catalog promotions use a focused prompt with the selected product name, saved price, and availability instead of stock-report fields. Local validation rejects inventory summaries, missing product names, price changes, unsupported discounts/scarcity, and missing invitations to reply. Invalid output receives one model-generated correction attempt; a second failure returns an error. No prewritten promotion is automatically substituted for model output. These checks are limited and do not guarantee all claims are factual.

Catalog product descriptions use a separate short prompt containing the name, category, and existing description, excluding stock and price fields. Validation rejects internal field reports, invented numbers, placeholders, and descriptive terms absent from the saved facts or a limited set of neutral writing words. This conservative vocabulary check can reject legitimate paraphrases and does not prove that existing catalog text is correct. Failed results get one model-generated correction attempt.

Description saves normalize empty strings and null consistently with the catalog mapper, so a blank description does not cause a false conflict. Real concurrent changes still block the save. **Reload current product** preserves the response and displays the latest description for comparison before another explicit save.

WhatsApp order replies, missed-call replies, review replies, and brand-voice rewrites use a customer-message prompt containing public catalog and fulfillment facts. They do not receive performance reports, purchase costs, margins, other customer records, or the order ledger. Availability replies receive up to five active, in-stock product names and selling prices, clearly described as a selection rather than the entire menu. Checks reject internal report fields, missing catalog answers, incorrect prices, premature personal-detail requests, and unsupported pickup/delivery offers. These checks are limited; review messages before sharing them.

Order delays has a separate read-only review: the server selects the signed-in business's oldest active orders (up to 100), displays up to 20, and calculates elapsed minutes from saved creation timestamps. Completed, cancelled, and draft orders are excluded. Limited results are labeled. The fact card is rendered directly from the server response, not generated by the language model. Elapsed time does not establish lateness when promised completion times are absent.

Local AI only supplies suggested next steps beneath the review. Validation rejects code/sample records, unknown order references, invented dates/numbers, financial fields, definite lateness claims, and completion promises. The verified review remains visible and downloadable if AI fails or the device lacks WebGPU. An empty active queue produces a factual empty state without model output. Actual on-device recommendation quality remains a separate check.

Promotion prices are compared by currency and numeric amount, so TT$60, TT$60.00, and TTD 60.00 represent the same price. Incorrect amounts, currencies, and extra recognized prices are rejected. Errors report the failing check instead of asking the user to simplify an app-provided starter. Repetition stops streaming and gets one correction attempt; persistent repetition returns an error. Quality failures retain the loaded engine; device/worker failures release it.

**Use saved product details** is an explicit alternative for Promotions. It refreshes the authenticated catalog, composes a short message from the selected product's saved name, price, and availability, and labels the result **From saved product details · No AI used**. It does not download a model, prepare an AI request, consume an AI generation, or write product records. The result can be edited, copied, downloaded, and opened in WhatsApp. Unavailable products invite an availability inquiry instead of an order. A later AI revision is labeled as AI output again.

Validation covers model variant selection, repetition repair and repeated-failure handling, price formatting/currency checks, refreshed catalog composition, model switching and persistence, explicit source labels, and mobile widths 320/390/1440. Browser tests mock the worker and application API. Actual model quality, load success, and generation speed on a physical iPhone remain to be tested.
